# ETLimit – notes for AI assistants working in this repo

- Target: VST3 only, Windows is the user's platform (CI builds it). Linux is used for development and tests.
- The user is new to C++/JUCE: explain decisions in plain language in comments and messages.
- DSP lives in `core/` (no JUCE). `plugin/` stays thin.
- Real-time rules in `docs/ARCHITECTURE.md` are mandatory: no allocation/locks/logging in `process()`, no fast-math.
- Add a parameter only when its DSP works. Never rename released parameter IDs or the plugin codes.
- Never report a test as passed unless it was executed. Use NOT RUN for checks that could not run. `docs/QA_REPORT.md` is generated by `tests/reference/make_report.py`, never hand-edited.
- Validate measurement tools before trusting them (see `tests/reference/selfcheck_truepeak.py`).
- Do not copy FabFilter (or any other product's) algorithms, names, styles or UI.

Build and test (Linux):

```
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure --output-junit qa/ctest.xml
```
